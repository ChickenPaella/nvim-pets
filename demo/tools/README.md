# 시연 클립 만들기

라이브 시연은 Google Meet 의 프레임레이트, LSP 로딩 지연, tmux 잔상에
전부 노출됩니다. 이 도구들은 같은 시연을 **한 번 정확히 녹화해서** 루프
GIF 로 굽습니다. 슬라이드에 넣어두면 설명하는 동안 계속 돌아갑니다.

```sh
pip install pyte pillow

python3 record.py     # 실제 nvim 을 pty 에서 구동해 바이트 스트림 녹화
python3 gif.py        # 비트별 루프 GIF 로 굽기 → clips/
python3 render.py --at 12 --at 20   # 특정 시점 프레임만 PNG 로 확인
```

## 어떻게 동작하는가

Kitty Graphics Protocol 이미지는 **터미널 에뮬레이터가** 그립니다. nvim 은
바이트만 내보내므로, 화면 캡처 없이 영상을 얻으려면 그 바이트를 직접
해석해야 합니다.

- **record.py** — nvim 을 pty 에서 띄우고 시연 키 입력을 순서대로 보내며
  출력 바이트를 타임스탬프와 함께 저장합니다. pty 에 **픽셀 크기까지**
  넘기는 게 중요합니다 (`ws_xpixel` / `ws_ypixel`). image.nvim 이 여기서
  셀 크기를 계산해 스프라이트를 확대하므로, 0 으로 두면 스프라이트가
  아주 작게 나옵니다.

  image.nvim 은 확대한 스프라이트를 임시 파일로 쓰고 터미널에는 **경로만**
  넘깁니다. nvim 이 종료할 때 그 디렉토리를 지우므로, 종료 직전에
  `sprites/` 로 복사해 둡니다.

- **render.py** — 스트림을 VT 에뮬레이터(pyte)에 흘려 텍스트 화면을 얻고,
  중간에 끼어 있는 `ESC _ G` 패킷에서 스프라이트 배치를 읽습니다. 그리는
  순서는 `z=-1` 을 그대로 재현합니다: 셀 배경 → 스프라이트 → 글리프.
  그래서 텍스트가 항상 스프라이트를 덮습니다.

  배치 추적에 함정이 하나 있습니다. image.nvim 은 새 프레임을 올린 직후
  이전 이미지를 지우므로, `a=d` 를 문자 그대로 처리하면 화면이 빕니다.
  대신 **틱 단위 배정**을 씁니다 — 같은 틱에 도착한 배치는 서로 다른
  스프라이트, 다음 틱의 배치는 같은 스프라이트가 이동한 것. 거리는
  동일 틱 안에서 짝을 고를 때의 기준일 뿐 문턱으로 쓰지 않습니다.
  문턱을 두면, 갇힌 펫이 화면 반대편으로 순간이동할 때 옛 위치가 유령으로
  남아 **방금 비켜난 코드 위에 앉아 있는 것처럼** 보입니다.

- **gif.py** — 비트별로 10fps 프레임을 뽑아 루프 GIF 로 굽습니다. 동일한
  연속 프레임은 직접 합치고 그만큼 지속시간을 넘겨줍니다. Pillow 의
  `optimize=True` 는 중복을 버리면서 지속시간을 더해주지 않아서, 정적인
  화면이 많은 클립이 3 배 빠르게 재생됩니다.

## Google 슬라이드에 넣기

삽입 → 이미지 → 컴퓨터에서 업로드. GIF 는 **발표 모드에서 자동 재생되고
계속 반복**됩니다. 재생 버튼도, Drive 업로드도 필요 없습니다.
