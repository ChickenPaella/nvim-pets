# Demo Day 시연

```sh
bash demo/demo.sh           # preflight → beat sheet → nvim 실행
bash demo/demo.sh --check   # preflight 만
bash demo/demo.sh --warm    # 幸福度를 100 으로 올린 뒤 실행
```

`demo.lua` 는 4비트가 전부 성립하도록 모양을 맞춘 버퍼입니다.

- 오른쪽 끝이 **일부러 들쭉날쭉**합니다 (긴 주석 줄 + 짧은 코드 줄).
  펫이 그 틈을 지나는 게 보여야 「코드를 밟지 않는다」가 전달됩니다.
- 코드는 39행에서 끝납니다. 그 아래가 비어 있어야 **공이 떨어질 자리와
  펫이 거기까지 갈 길**이 생깁니다. 화면이 코드로 꽉 차면 펫이 16틱
  (약 2.7초) 뒤에 포기합니다.
- 37행 끝의 `)` 가 BEAT 2 의 대상입니다. `demo.sh` 가 커서를 그 위에
  올려놓고 열기 때문에, 무대에서는 `x` 와 `u` 만 누르면 됩니다.

## 실측 타이밍

WezTerm 상당(`TERM=xterm-kitty`) 200×50 pty 에서 실제 설정으로 측정.
nvim 안에서 100ms 마다 상태를 파일에 기록해 얻은 값입니다.

| 조작 | 반응까지 | 유지 시간 |
|---|---|---|
| `:Pets` | 0.45초 | — |
| `x` (구문 깨기) | 0.65초 → `wiggle` +「!?」 | 1.9초 |
| `u` (되돌리기) | 0.65초 → `swipe` +「yay!」 | 1.9초 |
| `:PetsThrow` | 0.47초 → 전원 `approaching` | — |

**두 가지가 무대 진행을 바꿉니다.**

1. 반응이 0.65초 늦습니다. `x` 를 누른 뒤 **한 박자 쉬세요.** 바로 말을
   이으면 청중이 반응을 놓칩니다.
2. 반응이 1.9초만 유지됩니다. 놓치면 `u` → `x` 로 다시 만들 수 있습니다.

## 확인된 것

Kitty Graphics Protocol 패킷(`ESC _ G`)이 실제로 전송되는지 pty 출력
바이트에서 직접 셌습니다.

- `:Pets` 직후 11개, 시연 전체에서 830개
- `:PetsThrow` 구간에서만 407개 (4마리가 동시에 뛰므로 프레임이 많음)

또 `x` 를 눌렀을 때 lua_ls 가 실제로 `ERROR` 1건을 올리고, `u` 로 0건이
되는 것을 확인했습니다. 반응은 **에러 0 → 1 전이에서만** 발생하므로,
이미 에러가 있는 상태에서 하나 더 만들어도 아무 일도 일어나지 않습니다.

## 주의

- `:Pets` 는 lazy 스펙에 `cmd` 가 있어야 동작합니다. `keys` 만 있으면
  `<leader>pp` 를 누르기 전까지 `E492: Not an editor command` 가 납니다.
- lua_ls 워크스페이스 로딩에 약 1.7초. 그 전에는 BEAT 2 가 반응하지
  않으므로 파일을 열고 3초 기다린 뒤 시작하세요.
- 알림 팝업은 floating window 라서 blocked 그리드에서 제외됩니다. 펫이
  그 아래로 들어가 가려질 수 있으니 공유 전에 지워두세요.
