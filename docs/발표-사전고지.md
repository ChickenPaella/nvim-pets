# 발표 초반 고지용 — 실행 제약사항

> nvim-pets 는 Kitty 그래픽 프로토콜로 **실제 이미지**를 그린다. 아래 세 가지가
> 모두 맞아야 펫이 보인다. 하나라도 어긋나면 `:Pets` 는 에러 없이 실행되지만
> **아무것도 안 보인다.** (조용히 실패하므로 발표 전 반드시 확인)

## 슬라이드용 요약 (한 장)

**"쓰려면 세 가지가 필요합니다"**

| 항목 | 필요 조건 |
|---|---|
| **OS** | macOS 또는 Linux (Windows 네이티브 ❌) |
| **터미널** | Kitty · WezTerm · Ghostty 중 하나 |
| **이미지 처리** | ImageMagick 설치 (`brew install imagemagick`) |

한 줄 요약: **"맥/리눅스 + Kitty계열 터미널 + ImageMagick — 이 조합에서만 돕니다."**

## 자세히

### 1. OS
- ✅ **macOS, Linux** — 지원
- ❌ **Windows (네이티브)** — 미지원. image.nvim 과 ImageMagick 이 네이티브로
  안 돌고, Kitty·Ghostty 는 Windows 빌드가 없다.
- ⚠️ **Windows WSL2** — WezTerm + ImageMagick 조합으로 가능성은 있으나
  **미검증**. 라이브 데모용으로는 의존하지 말 것.

### 2. 터미널 (Kitty 그래픽 프로토콜 지원 필수)
- ✅ Kitty, WezTerm, Ghostty
- ❌ iTerm2 — 자체 이미지 프로토콜만 지원, Kitty 프로토콜 미지원
- ❌ macOS 기본 터미널, Alacritty, VS Code 내장 터미널 — 그래픽 프로토콜 없음

> **왜 Kitty 프로토콜만?** 펫이 코드를 가리지 않고 겹치고(z-index), 깜빡임 없이
> 이미지를 재전송이 아니라 ID로 재배치하는 이 동작들이 Kitty 프로토콜에서만
> 가능하다. 구식 프로토콜에선 매 프레임 재전송 → 깜빡이고 이미지가 쌓여
> 터미널이 얼어붙는다. 즉 이 제약은 "방해하지 않는 펫"을 위한 전제조건이다.

### 3. ImageMagick
- image.nvim 이 **런타임에** 스프라이트를 디코딩/렌더링할 때 쓴다.
  ("스프라이트 재생성 때만 필요"가 아니다 — 없으면 아예 안 보인다.)
- macOS: `brew install imagemagick` (dotfiles `install.sh` 가 자동 설치)
- 이 설정은 image.nvim `processor = "magick_cli"` 라 ImageMagick CLI 만 있으면
  된다 (별도 luarocks 설치 불필요).
- 확인: nvim 에서 `:checkhealth image`

### 4. tmux 를 쓴다면
`tmux.conf` 에 추가:
```tmux
set -g allow-passthrough on
set -g focus-events on
```

## 안 보일 때 자가진단 순서
1. `:checkhealth image` — image.nvim / ImageMagick 상태 확인
2. 터미널이 Kitty·WezTerm·Ghostty 인지 확인 (`echo $TERM_PROGRAM`)
3. tmux 안이면 위 passthrough 설정 확인
4. `:Pets` 두 번(껐다 켜기) — tmux 유령 프레임 클리어
